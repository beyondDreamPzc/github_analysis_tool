# 🩺 GitHub 仓库体检 · Repo Health Check

输入任意**公开** GitHub 仓库地址，一键生成可视化体检报告与 0–100 健康评分。

**零第三方依赖** —— 只需要 Python ≥ 3.8，不用 `pip install`。

---

## 一、功能介绍

### 1. 核心指标（全部来自 GitHub 公开 REST API）

| 板块 | 内容 |
| --- | --- |
| 仓库概览 | 简介、Topics、License、默认分支、创建时间、最近提交 / 发版时间、体积、README 与 CI 状态 |
| 热度指标 | Star、Fork、Watcher、Fork/Star 比值、衍生仓库数 |
| 语言分布 | 按字节数计算的占比环形图 + 图例进度条（GitHub 官方语言配色） |
| 活跃度 | 近 52 周提交趋势柱状图、近 30/90/365 天提交数、最近提交距今、发版节奏与平均发版间隔 |
| Issue 健康度 | 打开 / 关闭占比、关闭率、平均关闭耗时、官方社区健康度评分、最近 8 个 Release |
| 协作结构 | 贡献者总数、Top 10 贡献者排行、总线因子（头号贡献者占比）、Top3 占比 |

### 2. 健康评分（0–100，每一分可溯源）

五个维度加权求和，页面上可展开查看每个子因子的得分：

| 维度 | 权重 | 主要子因子 |
| --- | --- | --- |
| 社区影响力 | 25 | Star（对数刻度 14）、Fork（6）、Watcher（5） |
| 活跃程度 | 25 | 最近提交距今（10）、近 90 天提交数（8）、近一年发版次数（7） |
| 维护质量 | 20 | Issue 关闭率（6）、积压压力（4）、社区健康度（5）、README（3）、平均关闭耗时（2） |
| 协作广度 | 15 | 贡献者数量（8）、总线因子（4）、Top3 占比（3） |
| 工程规范 | 15 | License（3）、CI（3）、测试与工程化文件（2）、简介（2）、文档（2）、Topics（2）、版本标签（1） |

等级：`S ≥ 90 卓越` / `A ≥ 80 优秀` / `B ≥ 70 良好` / `C ≥ 60 一般` / `D < 60 待改进`

**封顶规则**（避免"看着很热其实已经死了"的项目拿高分）：

| 情况 | 处理 |
| --- | --- |
| 仓库已归档（archived） | 总分封顶 45，结论改判"不推荐" |
| 仓库已停用（disabled） | 总分封顶 20 |
| README 声明进入维护 / 废弃状态 | 总分封顶 70，结论改判"谨慎推荐" |

第三条是额外增强：很多项目没被 GitHub 归档，但 README 里已经写着 `maintenance mode`。工具会扫描 README 前 3000 字符识别这类信号，并给出命中的关键词与原文摘录，方便人工复核。

### 3. 其他

- **风险与亮点信号**：归档、超一年无提交、缺 License、未配置 CI、无测试目录、总线因子过高、Issue 积压、高热度但低活跃的"博物馆项目"，以及对应的加分项。
- **AI 项目点评**：总评 / 亮点 / 风险 / 可执行建议 / 选型结论。配了 AI Key 就调用大模型（任何 OpenAI 兼容接口），没配就用内置规则引擎生成同结构结论，页面会明确标注来源，不把规则结果伪装成 AI 输出。
- **数据完整性显式暴露**：10 个上游接口中若有失败，报告首条信号会写明「数据不完整（N 项接口采集失败）」并列出原因，避免把"取不到数据"误读成"项目不活跃"。
- 明 / 暗主题切换、5 张图表、一键导出 JSON 报告、`?repo=owner/name` 直接分享报告链接、响应式布局 + 打印样式（可直接打印成 PDF）。

## 二、项目目录结构

```
github-health-check/
├── server.py                  # HTTP 服务：静态托管 + API 路由 + .env 解析 + 静态资源指纹
├── .env.example               # 配置模板（复制成 .env 后生效）
├── .gitignore
├── lib/
│   ├── __init__.py            # 包标记
│   ├── github.py              # 数据采集：10 个接口并行聚合、缓存、错误归一化、维护状态扫描、中继回退
│   ├── score.py               # 五维评分引擎、风险信号识别、规则点评、AI 点评
│   ├── proxy.py               # 出网代理：代理优先级 / NO_PROXY / 熔断 / 失败回落直连
│   ├── relay.py               # 备用数据通道：镜像探测与自动切换（走中继不携带 Token）
│   ├── diag.py                # 出网诊断：DNS 保留地址识别 / 逐域名连通性 / 中继可用性 / 代理生效状态
│   └── env.py                 # 轻量 .env 解析（去引号 / 去尾随空格 / 剥离行尾注释）
└── public/
    ├── index.html             # 单页仪表盘
    ├── app.js                 # 渲染逻辑 + 5 个图表 + 失败面板与环境横幅
    ├── styles.css             # 明暗双主题样式
    └── vendor/chart.umd.js    # Chart.js 4.4.4（已本地化，离线可用）
```

## 三、启动方法

### 1. 拉取并启动

```bash
git clone <本仓库地址>
cd github-health-check

python server.py
```

启动后终端会打印页面地址与当前出网状态。浏览器打开：

```
http://localhost:8787
```

> 不需要 `pip install` —— 项目没有任何第三方依赖，Chart.js 已放在 `public/vendor/` 下。

### 2. 开始体检

在页面输入框粘贴任意公开仓库地址，点「开始体检」：

```
https://github.com/vitejs/vite
vitejs/vite
```

也支持直接用 URL 打开指定报告：`http://localhost:8787/?repo=vitejs/vite`

### 3. 可选配置

```bash
cp .env.example .env     # 全部留空也能跑，按需填写
```

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `PORT` | 服务端口 | `8787` |
| `GITHUB_TOKEN` | GitHub Token，配额 60 → **5000 次/小时**且独享 | 空（60 次/小时） |
| `GITHUB_PROXY` | 出网代理，如 `http://127.0.0.1:7890` | 空（直连） |
| `GITHUB_RELAY` | 备用通道开关：`off` 关闭；也可填自建网关前缀 | 开启 |
| `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `AI_MODEL` | AI 点评，兼容任何 OpenAI 协议的服务 | 空（用内置规则引擎） |
| `CACHE_TTL_MS` | 采集缓存时长，避免重复消耗配额 | `600000`（10 分钟） |
| `NO_PROXY` | 不走代理的域名白名单 | 空 |

> **改完 `.env` 必须重启服务** —— 配置只在进程启动时读取一次。
> 如果不想重启，也可以直接在页面右上角「⚙️ 高级设置」里填 Token，随请求头发送、立即生效。
> `.env` 已在 `.gitignore` 中，不会提交进仓库。

### 4. 验证服务状态

```bash
curl http://localhost:8787/api/health          # 服务探针 + 出网可达性 + 当前配额
```

浏览器直接打开 `http://localhost:8787/api/diag?format=text` 可以看到完整的出网诊断报告（DNS 解析、逐个域名连通性、备用通道可用性、代理是否真的生效）。

## 四、API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/analyze?repo=<url>&refresh=1` | 采集 + 评分，返回完整指标。命中缓存约 10ms；`refresh=1` 强制刷新 |
| POST | `/api/ai-review` | body `{repo, apiKey?, baseUrl?, model?, githubToken?}`，生成 AI 点评 |
| GET | `/api/health` | 服务探针（含出网可达性、代理生效状态、备用通道状态） |
| GET | `/api/limits` | 当前 GitHub API 配额 |
| GET | `/api/diag` | 出网诊断报告，加 `?format=text` 返回纯文本 |

单次体检约消耗 **10 次** GitHub API 配额；同一仓库 10 分钟内重复分析走缓存，不再消耗配额。

## 五、注意事项

1. **建议配 `GITHUB_TOKEN`。** 未认证时限额仅 60 次/小时（约可体检 7 个仓库），且这 60 次按**出口 IP 共享**，家宽 / 公司出口常被他人用光，表现为突然全部 `HTTP 403`（注意：这是限流，不是断网 —— 报错文案会明确区分）。
2. **代理走标准环境变量**：`HTTPS_PROXY` / `ALL_PROXY` 等与 `curl` / `git` 的读法一致，本工具另支持用 `GITHUB_PROXY` 覆盖环境里已有的代理。注意 `git config --global http.proxy` 只影响 git 自身，改变不了本工具的出口。
3. **代理不一定是好事。** 某些白名单代理只放行 `api.github.com` 的个别路径，会导致部分接口失败；工具按「连续失败 3 次」自动熔断 10 分钟并回落直连。
4. **网络受限环境**下会自动探测公共镜像作为备用通道。但中继不携带 Token，也绕不过配额，只解决"被封锁"，不解决"被限流"。
5. **采样上限**：贡献者、Issue、提交均按前 100 条采样（GitHub 分页限制），超大仓库的数值为采样估算，页面上已标注口径。
6. 仅支持**公开仓库**（GitHub 公开 API 不返回私有仓库数据）。
